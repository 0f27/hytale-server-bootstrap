# Hytale Server Bootstrap

One-script self-hosted Hytale dedicated server setup for **CachyOS / Arch Linux** using Docker.

Run a single command and get a fully configured, containerised Hytale server with persistent world data, automatic restarts, and UFW firewall rules.

---

## Requirements

- CachyOS or any Arch-based distro on **x86_64**
- A Hytale account that **owns the game** (Standard Edition or higher)
- `sudo` access
- Internet connection (~1.5 GB download for server files)

---

## Quick Start

```bash
mkdir hytale-server && cd hytale-server
curl -O https://raw.githubusercontent.com/yourname/hytale-server/main/hytale-server-bootstrap.sh
chmod +x hytale-server-bootstrap.sh
./hytale-server-bootstrap.sh
```

The script handles everything:

1. Installs missing dependencies via `pacman` (`docker`, `docker-compose`, `docker-buildx`, `wget`, `unzip`, `ufw`)
2. Detects kernel updates and prompts for reboot if needed (prevents Docker networking failures)
3. Enables and starts the Docker daemon via systemd
4. Downloads the official Hytale Downloader from `downloader.hytale.com`
5. Authenticates with your Hytale account (interactive, browser-based, skipped if already done)
6. Downloads and extracts the server files (~1.5 GB, skipped if already present)
7. Writes `Dockerfile`, `docker-compose.yml`, `jvm.options`, `.dockerignore`
8. Configures UFW: opens UDP 5520 (Hytale) and TCP 22 (SSH)
9. Builds the Docker image and starts the server

Re-running the script is safe — every step is skipped if already done.

## First Boot — Server Authentication

After the server starts you need to authenticate it **once** with your Hytale account.
This is separate from your account login and authorises the server itself to accept connections.

Attach to the server console:

```bash
docker attach hytale-server
```

Inside the server console type:

```
/auth login device
```

> **Important:** use `/auth login device`, not `/auth login`. The plain form tries to open
> a localhost callback URL which doesn't work inside Docker.

Visit the URL shown, enter the code, and approve in your browser. The server will confirm with a message. Then detach **without stopping the server**:

```
Ctrl+P  then  Ctrl+Q
```

Restart in the background:

```bash
docker compose down
docker compose up -d
```

The auth token is stored inside the container and persists as long as the container exists.
You only need to re-authenticate if you do a full rebuild (`docker compose build`).

## Connecting

From the **same machine**: `127.0.0.1:5520`

From **other devices on your LAN**: `<host-machine-ip>:5520`

In Hytale: **Servers → Direct Connect** and enter the address above.

> Share codes (the invite link from singleplayer) are not available on dedicated servers.
> Players always connect via Direct Connect.

## Directory Layout

After first run the folder looks like this:

```
hytale-server/
├── hytale-server-bootstrap.sh      # this script
├── Dockerfile                      # generated
├── docker-compose.yml              # generated
├── .dockerignore                   # generated
├── start.sh                        # from Hytale archive
├── Assets.zip                      # from Hytale archive (~3.4 GB)
├── Server/                         # from Hytale archive
│   ├── HytaleServer.jar
│   ├── HytaleServer.aot.config
│   ├── jvm.options                 # generated — edit heap here
│   └── Licenses/
└── data/                           # persistent state mounted from host
    ├── universe/                   # ← world data (the only thing you need to back up)
    │   ├── players/                #   player profiles
    │   └── worlds/default/         #   world chunks, resources, config
    └── backups/                    # ← periodic snapshots from start.sh
```

Everything inside `data/` is owned by UID 1500 (the `hytale` user inside the container).

## JVM Memory

Edit `Server/jvm.options` to tune heap for your machine. Default values assume ~16 GB RAM:

```
-Xms3g
-Xmx6g
```

Hytale requires a minimum of **4 GB heap** (`-Xmx4g`). Restart the container after changing:

```bash
docker compose down && docker compose up -d
```

## Migration

The only folder you need to migrate your world is `data/`. Everything else (server binaries,
Docker image, config) is regenerated by the bootstrap script on the new machine.

### Steps

1. Stop the server:
   ```bash
   docker compose down
   ```

2. Copy `data/` to the new machine (any method — `scp`, USB drive, etc.)

3. On the new machine, put `hytale-server-bootstrap.sh` in an empty folder alongside `data/`
   and run it:
   ```bash
   ./hytale-server-bootstrap.sh
   ```
   The script re-downloads the server binaries (~1.5 GB) using your Hytale account,
   rebuilds the image, and starts the server with your existing world.

4. Authenticate the server once on the new machine:
   ```bash
   docker attach hytale-server
   # then: /auth login device
   ```

> **Note:** Server binaries (`Server/`, `Assets.zip`, `start.sh`) cannot be redistributed
> per Hytale's terms. The script always re-downloads them on a fresh machine.

```bash
# Start in background
docker compose up -d

docker compose down

# Tail live logs
docker compose logs -f

# Attach to server console (detach with Ctrl+P Ctrl+Q)
docker attach hytale-server

docker compose down

# Re-authenticate after a rebuild
docker attach hytale-server

```

## Troubleshooting

**`Module bridge not found` / `veth` errors on build**
Your kernel modules don't match the running kernel — the system was updated without rebooting.
The script now detects this automatically and exits with a reboot prompt. After rebooting, re-run the script.

**`UID 1000 is not unique` on build**
The base Docker image already has a user at UID 1000. The Dockerfile uses UID 1500 to avoid this.
If you have an old Dockerfile lying around: `sed -i 's/useradd -m -u 1000/useradd -m -u 1500/' Dockerfile`

**`serverAuthUnavailable` when connecting**
The server hasn't been authenticated yet, or was rebuilt and lost its token.
Attach and run `/auth login device` — see First Boot above.

**World regenerated / empty after restart**
The volume mount for `universe` wasn't in place when the world was first created, so it lived
only inside the container. Copy it out before stopping:
```bash
docker cp hytale-server:/server/Server/universe/. data/universe/
```
Then restart with the correct `docker-compose.yml`.

**Server constantly restarting**
Usually a permissions issue — `data/` directories must be owned by UID 1500.
The script sets this automatically, but if you created directories manually:
```bash
sudo chown -R 1500:1500 data/
```

## Notes

- The server runs on **UDP port 5520** using the QUIC protocol
- For internet play: forward UDP 5520 on your router, or use [Tailscale](https://tailscale.com) for zero-config peer-to-peer VPN — no port forwarding needed
- Hytale's built-in backup runs every 30 minutes by default (`--backup-frequency 30` in `start.sh`) and writes to `data/backups/`
